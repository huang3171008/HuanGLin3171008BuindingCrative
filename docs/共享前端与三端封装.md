# 一核三端：界面、音频与构建说明

## 目录与同步

`shared-web/` 是唯一编辑入口，包含 `index.html`、`manifest.webmanifest`、`service-worker.js` 和 `assets/`：

```text
shared-web/
├── index.html / manifest.webmanifest / service-worker.js
└── assets/
    ├── engine.js / p2p.js / cloud-client.js  # 原规则和连接逻辑
    ├── enhance.css / enhance.js              # 布局、导航、设置和教程
    ├── platform-bridge.js                    # 原生接口能力探测
    ├── shader-bg.js                          # WebGL 天空和 CSS 降级
    ├── ripple-transition.js                  # 按钮反馈与非阻塞过渡
    ├── audio-manager.js                      # 音乐、音效与生命周期
    ├── music/bright-piano.mp3 / sunny-adventure.mp3  # 两首新增 CC0 音乐
    ├── music/overworld.mp3 / happy-loop.mp3  # 原来的两首 CC0 音乐仍可选择
    └── sfx/click.mp3 / switch.mp3 / confirm.mp3  # 已包含 CC0 按钮音效
```

在项目根目录运行 `node sync-shared.mjs`，会同步到 `android/assets/`、`desktop/app-assets/` 和 `ios/GuessingArena/web/`，并只清理两张退役的大纹理。Android 的 `build.ps1` 和另外两端的 `sync-assets.mjs` 也会执行同步。`game/cloud-server.mjs` 沿用同步后的 `android/assets/assets/engine.js`，不要只修改某个平台的复制品。`prepare-assets.mjs` 在音乐缺失时从注明来源下载并校验；离线构建需事先准备好音乐。

已核对题述两首 Freesound 作品均为 CC0，但原始下载要求登录。本版新增两首可离线使用的 OpenGameArt CC0 音乐“暖阳钢琴”和“快乐冒险”，原来的曲目仍可在菜单选择。旧版已选曲目更新后会映射到新曲，原本关闭音乐的用户保持关闭。按钮音效使用 Kenney CC0 的 UI Audio：`click1.ogg`、`switch1.ogg`、`click2.ogg` 经转码分别保存为 `click.mp3`、`switch.mp3`、`confirm.mp3`；素材和来源见第三方许可说明，文件缺失或解码失败时会回退合成音效。音量和开关分别保存在本机，第一次触摸解锁 Web Audio；后台暂停，恢复时尝试续播。浏览器、系统静音、后台策略及 MP3 循环处可能出现的间隙仍需各设备实测。

## Android

继续使用 Java Activity + WebView，`MainActivity` 仅将指定共享文件映射到本机 appassets，直连模式下原生顶栏隐藏，旧服务器模式保留原生返回入口；不开放任意文件。保留 WebView 默认的媒体用户手势要求，音频在用户点击时解锁。当前使用系统默认硬件加速；如特定设备禁用或 GPU 不支持，自动退化为 CSS。参见 [Android WebSettings](https://developer.android.com/reference/android/webkit/WebSettings#setMediaPlaybackRequiresUserGesture(boolean))。

设置 `JAVA_HOME`、`ANDROID_SDK_ROOT`，运行 `android/build.ps1` 后得到未签名 APK；使用与旧版相同的安全密钥签名才能覆盖安装。清除应用数据会丢失本地钱包；签名密钥不得提交仓库。测试包不代表正式发行、所有国产 WebView 或后台行为已验证。

## iPhone / iPad

继续使用现有 SwiftUI + WKWebView 工程，非 Capacitor。直接模式加载本机 loopback 静态资源，使用 `viewport-fit=cover` 和 CSS safe-area；`bounces=false`、inline media 和 ambient 音频会话。`Info.plist` 现有 `NSLocalNetworkUsageDescription` 用于原局域网连接；没有实现 Bonjour 扫描，不应凭空添加 Bonjour 服务声明。无 Mac 不能构建或签名 IPA；需要 macOS、Xcode、Apple 账号和真机逐项验证，参见 [WKWebViewConfiguration](https://developer.apple.com/documentation/webkit/wkwebviewconfiguration)。

PWA 过渡：把 `shared-web` 由可用 HTTPS 站点提供后，可用 `manifest.webmanifest`、图标与 Apple Touch 元信息添加到主屏幕。缓存仅用于静态外壳，云联机仍需要真实服务器；普通浏览器没有原生 LAN 桥，不能假称具备局域网房间码功能。iOS Safari/WKWebView 行为需真机测试。

## Windows / Tauri 参考

交付版继续使用 Electron，已配置隐藏标题栏和系统窗口控制区域、可拖动区域、Chromium 硬件加速的默认机制，不破坏现有 TCP LAN 桥。`examples/tauri-bridge/` 是 Tauri 2 **配置和 Rust 命令骨架**，不是已构建程序。要迁移必须建立真实 Tauri 工程并安装 Rust、WebView2 和对应 Tauri 依赖，把示例放到 `src-tauri` 后调整 `frontendDist` 相对路径，参考 `npm run tauri dev` / `npm run tauri build`。当前 CSP 因旧页面内联脚本包含 `unsafe-inline`，生产前应提取脚本并收紧；Tauri 剪贴板需启用 [clipboard-manager](https://v2.tauri.app/plugin/clipboard/) 最小权限。[Rust commands](https://v2.tauri.app/develop/calling-rust/) 需实现并注册现有 TCP LAN 协议，不能把返回错误的骨架称为已完成。要完全无边框时还需实现拖动、最小化、最大化和关闭；示例保留系统窗口框以防不可操作。

## 网络和实测

云房间仍需双方连接同一个可用 HTTPS/WSS 服务，8 位房间码不是服务器地址；当前没有部署国内服务器。依次在 Windows、Android、iPhone 真机验证每种组合的同 Wi-Fi、不同 Wi-Fi、Wi-Fi+蜂窝；覆盖创建、加入、准备、10 回合、两种竞猜、钱包流水、断线重连。LAN 直连还须验证本地网络权限、客户端隔离和原生 TCP 桥。分别记录真实设备、单机自动化、失败和未测试项目，不把本机双实例当成跨设备成功。
